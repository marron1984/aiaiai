# 将来ロードマップ — aiaiai

## 概要

本ドキュメントは、MVP（最小実行可能プロダクト）以降のaiaiaiの拡張計画をフェーズ別に整理する。各フェーズは前フェーズの安定稼働を前提とし、ユーザーフィードバックと運用データに基づいて優先度を調整する。

---

## フェーズ一覧

| フェーズ | 期間目安 | テーマ |
|---|---|---|
| **MVP** | 現在 | 基本収集・要約・公開・管理の確立 |
| **P1** | MVP安定後〜3ヶ月 | 配信チャネル拡張・重複排除精度向上 |
| **P2** | P1完了後〜6ヶ月 | 会員機能・外部連携・AI活用深化 |
| **P3** | P2完了後〜 | 多言語対応・高度アナリティクス |

---

## P1: 配信チャネル拡張・精度向上

MVP安定稼働後、情報の到達範囲を広げ、収集精度を高めるフェーズ。

### P1-1: X（Twitter）連携強化

| 項目 | 内容 |
|---|---|
| 目的 | SNS速報の取り込み精度向上と、公式情報との自動紐づけ |
| 機能 | X API v2を使用した公式アカウント投稿の定期取得 |
| 制約 | X利用規約を厳守（スクレイピング禁止、API/埋め込みのみ） |
| 実装内容 | ・公式アカウントのツイート取得Fetcher<br>・ツイート→RawItem変換Parser<br>・公式情報との自動マッチング（URL一致/キーワード一致）<br>・未検証→検証済み自動昇格ルール |
| 優先度 | 高 |

### P1-2: RSSフィード出力

| 項目 | 内容 |
|---|---|
| 目的 | RSSリーダーユーザーへの情報配信 |
| 機能 | aiaiaiの公開記事をRSS/Atom形式で配信 |
| 実装内容 | ・全記事フィード（`/feed.xml`）<br>・プロダクト別フィード（`/products/[slug]/feed.xml`）<br>・週次ダイジェストフィード（`/weekly/feed.xml`）<br>・フィードにはsummary3のみ掲載（全文転載防止） |
| 優先度 | 高 |

### P1-3: ニュースレター配信

| 項目 | 内容 |
|---|---|
| 目的 | メール購読者への定期配信 |
| 機能 | 週次ダイジェストをメールで自動配信 |
| 実装内容 | ・メール購読フォーム（トップページ・記事ページ）<br>・購読者リスト管理<br>・週次ダイジェストのHTML/テキストメール生成<br>・配信サービス連携（Resend / SendGrid等） |
| 優先度 | 中 |

### P1-4: 公開API

| 項目 | 内容 |
|---|---|
| 目的 | 外部開発者・サービスへの情報提供 |
| 機能 | REST API で記事・プロダクト・タグ情報を提供 |
| 実装内容 | ・`/api/v1/articles` — 記事一覧・検索<br>・`/api/v1/articles/[slug]` — 記事詳細<br>・`/api/v1/products` — プロダクト一覧<br>・レート制限（100リクエスト/時）<br>・APIキー認証（将来の有料プラン対応） |
| 優先度 | 中 |

### P1-5: セマンティック重複排除

| 項目 | 内容 |
|---|---|
| 目的 | URL・タイトル一致では検出できない意味的重複の排除 |
| 機能 | テキスト埋め込み（Embedding）による意味類似度判定 |
| 実装内容 | ・テキスト埋め込みモデルの選定（OpenAI text-embedding-3-small等）<br>・RawItemの埋め込みベクトル生成・保存<br>・コサイン類似度による重複候補検出<br>・管理画面での候補表示・統合操作<br>・閾値の調整機能 |
| 優先度 | 中 |

## P2: 会員機能・外部連携・AI活用深化

ユーザーエンゲージメントを深め、外部サービスとの連携を拡張するフェーズ。

### P2-1: 会員機能（保存・通知・レコメンド）

| 項目 | 内容 |
|---|---|
| 目的 | パーソナライズされた情報体験の提供 |
| 機能 | ユーザーアカウント、記事保存、通知設定、レコメンド |
| 実装内容 | ・ユーザー認証（NextAuth.js / OAuth）<br>・記事保存（ブックマーク）機能<br>・プロダクト別/テーマ別の通知設定<br>・閲覧履歴に基づくレコメンドエンジン<br>・ユーザーダッシュボード（保存記事一覧・通知一覧） |
| 優先度 | 高 |

### P2-2: Slack / LINE 連携

| 項目 | 内容 |
|---|---|
| 目的 | チームでの情報共有チャネルの拡大 |
| 機能 | Slack/LINEへの自動通知配信 |
| 実装内容 | ・Slack Incoming Webhook連携<br>・LINE Messaging API連携<br>・プロダクト別・ラベル別のフィルター設定<br>・通知フォーマットのカスタマイズ<br>・管理画面での連携設定UI |
| 優先度 | 中 |

### P2-3: AIチャットナビゲーション（RAG）

| 項目 | 内容 |
|---|---|
| 目的 | 自然言語での情報検索・質問応答 |
| 機能 | RAG（Retrieval-Augmented Generation）ベースのチャットUI |
| 実装内容 | ・記事データのベクトルDB格納（Pinecone / pgvector）<br>・質問に関連する記事の検索・取得<br>・LLM（Claude API等）による回答生成<br>・出典記事へのリンク付き回答<br>・チャットUI（サイドパネル形式）<br>・会話履歴の保存（会員のみ） |
| 優先度 | 中 |

### P2-4: 法人向けダッシュボード

| 項目 | 内容 |
|---|---|
| 目的 | 法人顧客向けのカスタマイズされた情報管理 |
| 機能 | 法人アカウント、チーム管理、カスタムフィード |
| 実装内容 | ・法人アカウント管理（チームメンバー招待・権限設定）<br>・カスタムウォッチリスト（監視プロダクト・キーワード選択）<br>・チーム内での記事共有・コメント<br>・CSV/PDFエクスポート<br>・法人向けAPI（高レート制限）<br>・請求管理（Stripe連携） |
| 優先度 | 低 |

## P3: 多言語対応・高度アナリティクス

グローバル展開と、データ駆動の意思決定基盤を構築するフェーズ。

### P3-1: 多言語対応

| 項目 | 内容 |
|---|---|
| 目的 | 日本語以外のユーザーへのリーチ拡大 |
| 機能 | 英語版サイトの提供、多言語要約生成 |
| 実装内容 | ・Next.js i18n（国際化）設定<br>・UIテキストの多言語化（日本語/英語）<br>・要約の自動翻訳（LLM API活用）<br>・言語切替UI<br>・hreflang設定（SEO）<br>・言語別URL（`/en/article/...`）<br>・将来的に中国語・韓国語への拡張 |
| 優先度 | 中 |

### P3-2: 高度アナリティクス

| 項目 | 内容 |
|---|---|
| 目的 | コンテンツ・ユーザー行動の深い理解と最適化 |
| 機能 | 独自アナリティクスダッシュボード |
| 実装内容 | ・ページビュー・ユニークユーザー・セッション計測<br>・記事別エンゲージメント分析（クリック率・滞在時間・直帰率）<br>・プロダクト別トレンド分析<br>・スコアリング精度の評価（CTRとスコアの相関分析）<br>・A/Bテスト基盤（見出し・要約のバリエーションテスト）<br>・スコアリング重み自動最適化<br>・リアルタイムダッシュボード |
| 優先度 | 低 |

### P3-3: 高度なコンテンツ生成

| 項目 | 内容 |
|---|---|
| 目的 | AIを活用したコンテンツ品質の向上 |
| 機能 | LLMによる高品質な要約・分析の自動生成 |
| 実装内容 | ・LLM API（Claude / GPT）による要約生成の高度化<br>・トレンド分析レポートの自動生成（月次）<br>・プロダクト比較記事の半自動生成<br>・要約品質の自動評価（ファクトチェック支援）<br>・ユーザーフィードバックに基づく要約スタイルの最適化 |
| 優先度 | 低 |

## 技術的な前提条件

各フェーズの実装にあたり、以下の技術的前提を満たす必要がある。

| フェーズ | 前提条件 |
|---|---|
| P1 | MVP安定稼働、日次Cronの成功率95%以上、管理画面の基本操作が機能 |
| P2 | P1機能の安定稼働、ユーザー認証基盤の構築、ベクトルDB環境の準備 |
| P3 | P2機能の安定稼働、月間アクティブユーザー数の一定規模到達、多言語コンテンツ運用体制の確立 |

## コスト見通し

| フェーズ | 主な追加コスト | 概算 |
|---|---|---|
| MVP | Vercel Free、PostgreSQL Free | 無料〜月額数百円 |
| P1 | X API（Basic: $100/月）、Embedding API、メール配信 | 月額$100〜$200 |
| P2 | LLM API、ベクトルDB、認証サービス | 月額$200〜$500 |
| P3 | 翻訳API、アナリティクス基盤、CDN拡張 | 月額$500〜$1,000 |

※ユーザー規模により大幅に変動する。法人プランの収益で相殺を想定。

## 優先度の判断基準

以下の基準で各機能の優先度を判断する。

| 基準 | 重み | 説明 |
|---|---|---|
| ユーザー価値 | 高 | ユーザーの情報収集効率をどれだけ改善するか |
| 実装コスト | 中 | 開発工数・運用コスト・外部サービス費用 |
| 差別化効果 | 中 | 競合サービスとの差別化にどれだけ寄与するか |
| 収益貢献 | 低（MVP段階） | 将来の収益化にどれだけ寄与するか |

## リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| X API料金改定 | P1のコスト増大 | API依存度を下げる設計、埋め込み中心に切替可能に |
| LLM API料金高騰 | P2/P3のコスト増大 | モデル切替可能な抽象化層、キャッシュ活用 |
| 法規制の変化 | コンテンツ運用の変更 | 法務メモの運用、削除依頼対応フローの整備 |
| 競合サービスの出現 | ユーザー流出 | 差別化ポイント（重複統合・スコアリング）の強化 |
| スケーラビリティ | パフォーマンス劣化 | キャッシュ戦略、DB最適化、CDN活用 |
